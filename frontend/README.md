# AKIM AI — frontend

«Аким на 5 часов»: интерфейс учебной симуляции управления Астаной. Синтетические данные организаторов, пять районов, 14 инициатив, бюджет 100, ровно пять решений. Только frontend; математический движок и AI принадлежат другим участникам.

## Запуск

Нужен Node.js 22.20+ и npm. Из корня репозитория:

```bash
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. По умолчанию включён **демонстрационный режим**. Ключ API, отдельный сервер, платные сервисы и внешняя карта не нужны.

Production:

```bash
npm run build
npm start
```

Адрес привязан к 127.0.0.1 для локальной разработки. При контейнеризации интегратор может запустить `npx next start --hostname 0.0.0.0 --port 3000` за настроенным reverse proxy. Не менять общий Docker Compose из frontend-ветки.

## Демонстрация за две минуты

1. На главной нажать «Начать управление».
2. Выбрать район, посмотреть десять показателей, отфильтровать каталог. В карточке меры открыть детали, выбрать район, посмотреть задержки и полные эффекты.
3. Нажать «Попробовать пример»: M7, M8, M10 в Нуре, M12 по городу и M5 в Сарыарке. Расход — 95, остаток — 5, пять решений.
4. «Рассчитать результат»: показать сохранённый контрольный ответ 52.55768 → 56.54307, сравнение районов и 10 показателей, radar chart, исчезновение критических значений, синергию и задержки.
5. Показать объяснение с явной отметкой «Шаблон · не AI». Сохранить план и перейти в сравнение. Для двух колонок сохранить ещё один план; одинаковые планы честно показывают одинаковые результаты.
6. Для произвольных наборов mock не считает Score, не проверяет доменные конфликты и не имитирует AI. Отображается необходимость подключения backend. Это намеренная граница ответственности.

## Подключение backend

Скопировать `.env.example` в `.env.local` и задать:

```dotenv
NEXT_PUBLIC_API_MODE=live
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000
NEXT_PUBLIC_ENABLE_RECOMMENDATIONS=false
```

Перезапустить dev-сервер или пересобрать production. Base URL без `/api`. Сервер должен разрешать CORS для origin фронтенда. API-ключи никогда не помещать в NEXT_PUBLIC-переменные.

**Перед подключением прочитать [INTEGRATION.md](./INTEGRATION.md).** Это предложение контракта, опубликованное до появления серверного. Обязательный источник правды после согласования — `shared/api-contract.md`, которым владеет интегратор. Весь сетевой обмен находится в `lib/api.ts`; преобразования формата делаются там, без редактирования backend.

## Что реализовано

- `/`: старт, правила и ограничения модели.
- `/simulator`: бюджет, 5 слотов, preview, схема районов с управлением с клавиатуры, десять показателей, каталог и поиск, подробности инициатив, удаление и очистка решений, предупреждения сервера, синергии.
- `/results`: итог до/после, районы, таблица всех показателей и radar chart, критические показатели, слабейший район, вклад мер из API, timeline задержек, AI-панель с независимой обработкой ошибки и повтором, сохранение и JSON-экспорт.
- `/compare`: до двух сохранённых сценариев, расходы, Score, слабейший район, критические показатели, различия решений и версии модели.
- Черновик и до 12 сценариев в localStorage, проверка повреждённых данных, уведомление о недоступном хранилище.
- Обработка loading/empty/error/success, HTTP 422, таймаутов, потери сети и неподходящей схемы ответа.
- Адаптивный интерфейс, focus states, именованные действия, Radix dialog с focus trap/Escape, reduced-motion.
- Кнопка «Улучшить одной заменой» включается флагом только после появления согласованного endpoint. Поиск выполняет backend.

## Стек и структура

Next.js App Router, React, TypeScript strict, Tailwind CSS 4, shadcn-compatible локальные Button/Dialog на Radix, Recharts, Lucide, Zod. Версии закреплены package-lock.json. Стили и SVG-схема локальные; шрифты системные, внешних CDN нет.

```text
app/                 страницы и адаптивные стили
components/          интерфейс и состояние сценария
components/ui/       Button и Dialog
lib/api.ts           единственная точка HTTP-запросов
lib/types.ts         типы и проверка ответов Zod
lib/fixtures.ts      буквальные официальные данные и один контрольный ответ
lib/storage.ts       версионированное браузерное сохранение
lib/*.test.ts        проверки API-границы и сохранения
INTEGRATION.md       предложение формата для интегратора
REQUIREMENTS.md      разбор четырёх PDF и границ роли
```

Frontend не содержит формулу Score, математический движок, реализацию синергий, перебор альтернатив или прямой вызов LLM. Простое отображение расходов, delta показателя и положения задержки на timeline не заменяет simulation engine.

## Проверки

```bash
npm run test
npm run typecheck
npm run lint
npm run build
```

Тесты проверяют не формулу, а границу фронтенда: формат и ошибки API, таймаут, независимость fixtures, запрет fake-результата для другого набора и надёжность сохранений. Полный расчётный и AI end-to-end проверяется после подключения серверных модулей по сценарию в INTEGRATION.md.

## Ограничения

- Полноценные расчёты пользовательских наборов, live-preview конфликтов/синергий, вклады и настоящий AI требуют backend. Mock рассчитан только на демонстрацию UI и не скрывает это.
- Нет серверного хранения, рейтинга команд, авторизации или географически точных границ. Карта подписана как схема.
- Нет экспериментальных событий и экспорта презентации: они опциональны в ТЗ. Доступен JSON-экспорт результата.
- Нельзя гарантировать отсутствие будущих конфликтов: в этой ветке изменены только `frontend/**`, а интеграция требует согласования API и общей проверки.
