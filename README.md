# AKIM AI — «Аким на 5 часов»

Учебный симулятор управления Астаной на синтетических данных HackAlem. Пользователь распределяет бюджет 100 между ровно пятью мероприятиями; сервер проверяет ограничения, рассчитывает последствия для пяти районов и Astana Quality of Life Score. AI объясняет уже рассчитанные факты.

Эта ветка реализует часть **BACKEND / SIMULATION / INTEGRATOR**. Next.js-интерфейс разрабатывается в `feature/frontend`, AI и отчёты — в `feature/ai`. Их код не подменяется заглушками. Backend самостоятельно запускается и считает без AI-ключа. Настоящий AI доступен после объединения AI-ветки и настройки провайдера.

## Запуск backend

Требуется Python 3.11+ (проверка ведётся на Python 3.12). Команды из корня репозитория.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Для runtime без инструментов тестирования достаточно `backend/requirements.txt`. Каталог `shared/` должен находиться рядом с `backend/`; загрузка данных не зависит от текущей рабочей директории.

Откройте [Swagger UI](http://127.0.0.1:8000/docs). Health: `GET /api/health`. Выполните `POST /api/scenario/finalize` с содержимым [контрольного сценария](shared/example-scenario.json): результат 56.54307, стоимость 95, базовый Score 52.55768. Затем вызовите `/api/recommend` с тем же запросом для проверенной замены одного решения.

## Frontend и API

Общий договор — [shared/api-contract.md](shared/api-contract.md). Форматы согласованы с `frontend/INTEGRATION.md` и Zod-типами фронтенда. Публичный JSON camelCase; район Есиль имеет ID `esil`. OpenAPI доступен на `/openapi.json`; воспроизводимые ответы находятся в `shared/fixtures/`.

Для Next.js после объединения frontend-ветки:

```dotenv
NEXT_PUBLIC_API_MODE=live
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000
NEXT_PUBLIC_ENABLE_RECOMMENDATIONS=true
```

Перезапустите/пересоберите frontend после изменения NEXT_PUBLIC-переменных. Backend CORS по умолчанию разрешает `http://localhost:3000` и `http://127.0.0.1:3000`; `CORS_ORIGINS` в окружении backend меняет список (через запятую). Ключи AI никогда не передаются в браузер.

## Проверки

После активации окружения:

```bash
cd backend
python -m pytest --cov=app --cov-report=term-missing
python -m ruff check app/api/simulation app/models app/simulation app/main.py tests scripts
python -m ruff format --check app/api/simulation app/models app/simulation app/main.py tests scripts
cd ..
python backend/scripts/export_fixtures.py
node backend/scripts/check_frontend_contract.mjs
python backend/scripts/check_ai_contract.py
```

Последние две команды выполняются после объединения и установки соответствующих модулей. До объединения можно передать внешний frontend-каталог вторым аргументом Node-скрипта, AI — `--ai-root /путь/backend/app`. AI-тесты используют контролируемый ответ провайдера и не расходуют API-кредиты.

Тесты проверяют точные контрольные числа, ограничения, отрицательные эффекты, задержки, синергии, значения 0/40/100, независимость от порядка, параллельные запросы, сохранение суммы вкладов и исчерпывающий поиск одной замены. Неверный набор никогда не получает официальный Score. AI-ошибка не ломает расчёт.

## Подключение AI после объединения ветки участника №3

Установите `python -m pip install -r backend/requirements-ai.txt`. Создайте локальный `backend/.env` по примеру AI-участника и задайте `OPENAI_API_KEY`, а также `OPENAI_MODEL`, доступную вашему API-проекту. Переменные процесса имеют приоритет над .env. Перезапустите сервер. В `/api/health` появится `aiConfigured=true`; это не проверка доступности провайдера. Настоящий AI-вызов выполняется только по запросу анализа/отчёта. Без настройки возвращается 503, без поддельного AI fallback.

Текущий frontend отправляет `{scenario: ...}` и получает выводы с evidence. Backend заново рассчитывает decisions и передаёт AI только свои числа. Поддерживается и первоначальная обёртка `{simulation: ...}`. Подробности — в API-контракте.

## Docker

Для расчётного backend предусмотрена команда `docker compose up --build`. Порт доступен только локально: 127.0.0.1:8000. Образ работает от непривилегированного пользователя и не копирует .env. Docker-конфигурация не включает frontend и AI SDK; для полного AI-режима используйте запуск Python выше. Сборку Docker нужно проверить там, где установлен Docker: в среде разработки этой части он отсутствовал.

## Модель и архитектура

`shared/districts.json`, `measures.json`, `model.json` содержат пять районов, десять индикаторов и 14 мероприятий из таблиц организаторов. [Анализ всех четырёх документов](backend/docs/requirements-analysis.md) фиксирует правила, расхождения и принятые решения.

`backend/app/simulation/` — единственный расчётный модуль; `models/` — Pydantic DTO; `api/simulation/` — HTTP и адаптер к AI; `main.py` — сборка FastAPI. Никакой БД или регистрации для MVP не требуется. Сценарии сохраняет браузер.

Эффект меры = полный эффект × (8 − lag) / 8. Фиксированные синергии прибавляются без лага, затем индикаторы ограничиваются 0–100. Оценка района — взвешенная сумма десяти индикаторов. `Score = 0.7 × среднее по населению + 0.3 × оценка слабейшего района − число индикаторов < 40`.

Расчёты используют точные рациональные числа (`Fraction`), без промежуточного округления. JSON содержит обычные числа; UI может округлять их для отображения. Shapley-вклады делят нелинейные эффекты между мерами и в сумме дают delta Score. Поиск рекомендаций гарантирует лучший допустимый результат **с одной заменой**, а не глобальный оптимум.

## Ограничения и интеграция

- Датасет синтетический; результаты нельзя выдавать за реальные прогнозы города.
- По подробному датасету допускаются две меры одного направления, поэтому не обязательно покрывать все пять направлений. Команде следует подтвердить эту трактовку краткого ТЗ у организаторов.
- Preview содержит предварительный after.score; официальный корневой score появляется только после допустимой финализации.
- AI требует модуля участника №3, установленного SDK, `OPENAI_API_KEY` и доступной `OPENAI_MODEL`. Без них API анализа возвращает честный HTTP 503, а расчёты работают. Прямые AI-роутеры, принимающие клиентские числовые факты, не подключаются: интегратор пересчитывает решения и использует AI service.
- Отчёты используют AI-owned формат ExecutiveBrief; рейтинги команд, события, PDF/PPT-экспорт и постоянное серверное хранение не входят в эту backend-часть.
- Нельзя гарантировать отсутствие ошибок после будущих изменений участников. Контракт, отдельные зоны владения и воспроизводимые тесты предназначены для выявления несовместимостей до объединения.
