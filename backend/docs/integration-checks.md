## Что не заявляется проверенным

Полный рендер Next.js в этой среде не выполнен: запуск блокируется Windows-ошибкой `spawn EPERM` при создании дочернего процесса. Проверен именно настоящий API-клиент фронтенда по HTTP, а также его runtime-схемы. Визуальную проверку выполняет владелец frontend.

После предоставления ключа выполнена отдельная реальная проверка OpenAI API: доступ к `gpt-6-astra` подтверждён, вызов `/api/ai/analyze` через FastAPI TestClient и настоящий AI-провайдер вернул HTTP 200 за 13.4 секунды. Ответ прошёл Pydantic-модель backend, настоящий `aiResponseSchema` и `normalizeAnalysis()` frontend. Контрольные числа в тексте совпали с серверным расчётом. Ключ в этот коммит не включён.

Первый запрос завершился `APITimeoutError` на штатном лимите 15 секунд; успешный диагностический запрос использовал лимит 60 секунд. Настройки рабочего backend (15 секунд) и frontend (20 секунд) не менялись. Это один успешный запрос, а не подтверждение стабильной задержки: перед демонстрацией нужен повторный прогон с новым ключом и согласование лимитов, если таймаут повторяется. Мок-тесты по-прежнему используют контролируемый провайдер.

В AI-модуле есть предупреждения об устаревших Pydantic `.dict()`/`.parse_obj()`; на закреплённой Pydantic 2.13.5 они работают. AI-код не редактировался; при миграции на Pydantic 3 его владельцу потребуется заменить эти вызовы.

Docker здесь не установлен, поэтому образ не собирался. В репозитории есть Dockerfile, compose и CI-проверки; локальный Python backend и его HTTP-запуск проверены.

## Перед объединением

Объединять через PR с сохранением текущего main. Feature-ветки frontend и AI добавляют свои директории; backend-папки и shared принадлежат интегратору. Не подключать AI `create_ai_router()` поверх интеграционного адаптера: один и тот же путь появится дважды и обойдёт серверный пересчёт. Сохранить текущие `app.main` и общий контракт.

После объединения: установить backend requirements-dev/requirements-ai и frontend-зависимости; запустить команды README; выставить frontend live-режим; выполнить контрольный сценарий и один реальный AI-анализ с настроенной моделью. Любые изменения данных требуют повторной генерации fixtures и проверки контрольных чисел.
